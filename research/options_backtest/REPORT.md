## 2. 本轮补齐了什么

上一轮 `collect_history.py` 的采集在途中被中断，两个标的都停在靠新的位置：

| 标的 | 中断时已存 | 起止 | 占目标根数 |
| --- | ---: | --- | ---: |
| BTCUSDT | 9 页 / 9,000 行 | 2025-11-04T09:00Z → 2026-11-14T08:00Z | 19% |
| ETHUSDT | 11 页 / 11,000 行 | 2025-08-13T01:00Z → 2026-11-14T08:00Z | 23% |

且因为没有跑 `analyze`，`hourly/`、`daily08/`、`manifest.json` 当时都不存在。

本轮给采集器加了 `--fill` 续采模式：从各标的**已存最旧一根**继续向前翻页，
不重取已有页，因此原有 9/11 页的 `receivedUtc` 采集时点（2026-11-14T17:00Z）
被完整保留，可与本轮新页（2026-11-14T17:28Z）区分。结果：

- BTCUSDT 补第 9–46 页，ETHUSDT 补第 11–46 页；
- 每标的 47 页，每页 1,000 行，仅最旧一页 989 行（起点受可用性下界所限）；
- 页链向后连续（每页最旧一根正好是上一页最旧一根减 1 小时），无断页；
- 目标区间内的 K 线一根不缺：**46,988 根/标的**。

## 3. 重复、缺口与时间边界

| 检查项 | BTCUSDT | ETHUSDT |
| --- | ---: | ---: |
| 小时线根数 | 46,988 | 46,988 |
| 覆盖区间 | 2021-07-05T12:00Z → 2026-11-14T07:00Z | 同左 |
| 末根 END | 2026-11-14T08:00Z（= 截止） | 同左 |
| 重复时间戳 | 0 | 0 |
| 冲突重复（同一时间戳不同数值） | 0 | 0 |
| 内部缺口 | 0 | 0 |
| 非整小时对齐 | 0 | 0 |
| 落在请求区间外的 K 线 | 0 | 0 |
| OHLC 越界/非法 | 0 | 0 |
| 零成交额 K 线 | 0 | 0 |
| 越界结束（END > 截止）的 K 线 | 0 | 0 |
| 相邻根 `open` = 前根 `close` | 46,982 / 46,987（99.989%） | 46,979 / 46,987（99.983%） |
| 相邻根开收差异绝对值上界 | 0.0722% | 0.0354% |
| `hourly/*.csv` 与 raw 页逐行一致 | 是 | 是 |

### 上界（截止语义）

小时线最后一根 `start=2026-11-14T07:00Z`，`END=08:00Z`，正好落在截止点上。
再往后一根（`start=08:00Z`）只保留 `open`，其余字段在 raw 中写成
`OMITTED_AFTER_CUTOFF`，且**不进入** `hourly/*.csv`。校验确认全库只有这一根被
截断，没有第二根越过截止的 K 线。截止之后的信息按本仓库既有纪律一律丢弃，
不得进入回测。

### 下界（可用性边界，不是采集缺口）

请求起点写的是 2021-07-05T00:00Z，但 **Bybit 现货小时线最早只到
2021-07-05T12:00Z**——当天 00:00–11:00Z 那 12 根交易所没有数据，采集器翻到
更早时接口返回空列表。这是来源边界，manifest 里单列为
`unavailableBeforeSourceFloorBars: 12` / `unavailableBeforeSourceFloorUtc`，
与"内部缺口"分开记账。独立探针（直接问 2019、2020、2021-01、2021-03、
2021-06 各窗口）全部返回空数组，确认不是翻页逻辑漏取。

因此任何"覆盖更长历史"的结论都不成立：可用历史从 2021-07-05T12:00Z 开始。

### daily08 锚点

`daily08` 每行取 08:00Z 那根的 `open`，`signal_close` 取 07:00Z 那根的 `close`，
`previous_daily_close` 取前一行的 `signal_close`。覆盖 2021-07-06T08:00Z →
2026-11-14T08:00Z，1,958 行；缺 1 个锚点 2021-07-05T08:00Z，因为当日的 08:00Z
小时根本不存在（源可用性下界在 12:00Z）。

## 4. 独立交叉校验

两条校验用的是**另一次采集、另一次脚本**的既有快照，可以独立暴露错位、错值或
静默截断：

**对 `research/data/1h/klines/`（40 对小时线探索快照，2024-01-01 →
2026-11-01T16:00Z）**

- 重叠 24,857 根，OHLCV 全字段逐值一致；仅 1 根不一致 = 该数据集的**最后一根**
  2026-11-01T16:00Z。逐字段看是同 `open`、`high/low/close` 更低、成交量只有约
  1/10 —— 这是采集时该小时尚未收盘的半根 K 线；本数据集这里是收盘后的完整根。
- 该旧数据集本身连续（无缺口），且其时间戳集合是新数据集的真子集。

**对 `research/data/klines/`（384 对日线快照，2021-07-05 → 2026-11-01）**

- 把小时线按 UTC 日聚合成 OHLC，与日线快照逐日比较：1,945 个完整日全部一致；
- 唯一不一致的是 2026-11-01，即日线快照采集当天的 partial bar。

两项交叉校验一致指向同一个解释：新补的历史没有错位、没有错值，两处差异都是
旧快照在采集时刻本身不完整。

## 5. 这批数据能用来做什么、不能替代什么

**能**：作为模拟定价的标的输入。可以用它重建价格路径、已实现波动率、收益率
分布，做希腊字母近似、离散事件/蒙特卡洛定价、以及"如果持有这个结构会怎样"的
口径化推演。

**不能替代历史期权真实报价**。本次采集没有、也无法获得：

- 期权历史 bid/ask、mark/IV 曲线、微笑与期限结构、OI、逐分钟成交；
- Bybit 期权结算用的 **index price 历史**（现货收盘 ≠ 结算价，指数成分与现货
  盘口不同，用现货收盘代结算会引入基差误差）；
- 实际费率与费率档位、跨保证金账户结构、保证金占用与强平规则历史；
- 期权流动性与可成交性（价差、最小手数、深度）。

因此用这批数据做的期权结果**只能称为模拟定价**（现货路径 + 模型化的 IV/微笑
假设），不能表述为期权策略的历史回测结论，也不能当作真实可成交的收益证据。
参考同期公开快照（`research/2026-11-15-bybit-options/`）：BTC 近端 mark IV 54.57%
对 7 日已实现波动率 43.70%，ETH 68.64% 对 62.50%——不同期限的历史与前瞻口径
之差，本身就不能用现货 RV 代替。

另需注意：现货小时线不含期权隐含波动率的偏斜与期限结构；对 BTC/ETH 这类
流动性最好的标的，期权与现货的基差和跳跃风险仍是主要尾部来源。
