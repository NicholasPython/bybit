# 双腿价差套利标的池协整性重评估（PRD FR-07.1）

日期：2026-11-23。本阶段落地 PRD FR-07.1 的**离线**部分：用真实的小时级公开行情判断某个价差配对的协整关系是否仍然成立，并给出"保留 / 剔除 / 提名"的清单供人工审阅。

接在[阶段三](spread-arbitrage-phase3-2026-11-22.md)与[影子盘](spread-arbitrage-shadow-2026-11-22.md)之后，属于 PRD 架构里的"人工控制与离线进化平面"，**不碰实时执行代码**。

## 一、结论摘要

- 本次实跑（60 天小时级、流动性前 50 个 U 本位永续、48 个可用）给出的结果：**当前在册配对 `BTCUSDT:ETHUSDT` 没有通过协整检验**（Engle-Granger 残差 ADF t = -1.655，p ≈ 0.654 > 0.05），按 PRD 的规则属于"协整关系破裂"；同时 10 个新配对通过全部判据，进入提名清单等待人工审阅。
- 两条腿本身都是 I(1)（各自 ADF 不拒绝单位根），因此"不协整"不是某条腿退化成平稳序列造成的假象；前后半段只有 1/2 段通过，关系本身也不稳。
- 相关性 0.978 与协整是两件事：BTC 与 ETH 的对数价格高度同步，但它们的**对数价差**不是平稳过程。这是本次最值得记下来的一条。
- 本阶段**只产出报告**：不改配置、不写数据库、不启用任何执行开关、不灰度、不实盘晋级。剔除与提名都要人工决定。

## 二、PRD 对应与边界

PRD FR-07.1 原文：*"自动获取交易所流动性前 50 合约过去 60 天的小时级数据，运行 ADF 检验与 Engle-Granger 协整检验，自动剔除协整关系破裂（p-value > 0.05）的币对，提名新合格币对。"*（每周日 UTC 02:00 由离线进化引擎执行）

边界：

- 数据只有 Bybit V5 **公共** REST（`tickers` / `instruments-info` / `kline`），不装载任何凭据，不发任何写请求；
- 不写业务库、不改 `config.yaml`、不改 `spread.*` 的执行面字段；
- 结论只是人工审阅材料：真正把某个配对变成"在册"仍然要走配置改动与影子盘 7 天验证（FR-07.3）。

## 三、方法与口径

### 3.1 单位根检验（ADF）

回归式 `Δy_t = α + γ·y_{t-1} + Σ δ_i·Δy_{t-i} + ε_t`，原假设为"存在单位根"。

- **规格**：含常数项（`c`），不含趋势项。含趋势项（`ct`）的 MacKinnon 临界值对应的是"确定性线性趋势"的数据生成过程，用在随机游走的价格上会严重高估拒绝率 —— 本模块实测 5% 水平上的误拒率会从 5% 抬到 31%，因此不作为默认口径。
- **滞后阶数**：可固定（默认 2 阶，批量扫描用）或按 BIC 在 `0..12` 中选择。
- **临界值**（MacKinnon 1994 渐近值）：`c` 规格为 -3.43 / -2.86 / -2.57（1% / 5% / 10%）；协整残差用 Engle-Granger 两变量无协整向量表 -3.90 / -3.34 / -3.04。

### 3.2 协整检验（Engle-Granger 两步法）

1. 对两条**对数价格**做 OLS：`y = a + β·x + e`；
2. 对残差 `e` 做 ADF；H0 为"两序列不协整"。

半衰期取残差 AR(1) 系数 `φ` 的 `-ln2/lnφ`；`φ` 不落在 (0,1) 时视为没有均值回复。

### 3.3 p 值是近似值

运行环境没有 statsmodels，p 值由临界值表插值得到：以 `(5% 临界值, 0.05)` 与 `(10% 临界值, 0.10)` 为锚点，按标准正态分位点线性映射后取尾概率。三张表在 1% 临界值处的插值结果落在 0.009～0.018 之间。**判定一律以 5% 临界值比较为准**，不依赖 p 值的精确数值；报告里的 p 值只用于排序和阅读。

### 3.4 提名要同时过三道判据

| 判据 | 目的 | 做法 |
| --- | --- | --- |
| EG 在 5% 水平拒绝"不协整" | PRD 的原始判据 | 残差 ADF 统计量 < -3.34 |
| 两腿都是 I(1) | 一条腿本身平稳时，"价差平稳"没有均值回复含义 | 两条腿各自的 ADF 都不拒绝单位根 |
| 前后半段都通过 | 单段检验在趋势型标的上容易给出假协整 | 样本对半切开各做一次 EG，两段都拒绝才算稳定 |

另外排除**同一标的的不同合约**（例如 `BTCUSDT` 与 `BTCPERP` 的 base coin 都是 BTC）：这种"配对"的价格差只是计价口径差异，没有可做的价差。

## 四、实现与目录

| 文件 | 职责 |
| --- | --- |
| `research/cointegration/cointegration.py` | 纯统计：ADF、Engle-Granger、半衰期、p 值插值、配对评估。零 I/O。 |
| `research/cointegration/pool.py` | 公开数据采集（白名单 + SSH→NAS 标准库）、标的池构建、小时线整理、配对批量评估与归档。 |

统计口径全部自研，**没有引入任何新依赖**（仓库里没有 numpy/scipy/statsmodels，部署镜像的依赖清单保持不变）。

### 4.1 取数通道

本机直连交易所的出口不通（`SSL_ERROR_ZERO_RETURN`），因此取数走仓库既有的 SSH→NAS 通道：请求参数先在本地过白名单，再把一段只读的标准库程序送到 NAS 执行，远端只用 `urllib` 发 GET，不携带任何凭据。批量请求按固定间隔铺开，并对 `retCode=10006`（按窗口限频）做 5 秒退避重试。

白名单只放行三个 linear 公共只读端点，K 线只允许 `interval=60`、`limit=1000`、符号必须是大写字母数字，且 `start < end`。

### 4.2 复跑

```bash
python research/cointegration/check_pairs.py \
  --out var/cointegration/2026-11-23-top50 \
  --pair BTCUSDT:ETHUSDT
```

常用参数：`--days`（默认 60）、`--top`（默认 50）、`--adf-lag`（整数或 `auto`）、`--min-observations`（默认 500 根小时线）、`--max-nominees`（默认 10）、`--reuse-data`（复用输出目录里的 `hourly-closes.json`，复算时不再取数）。

原始小时线缓存在输出目录的 `hourly-closes.json`，报告是 `cointegration.json` 与 `cointegration.md`。

窗口 2026-09-24 04:00Z ～ 2026-11-23 04:00Z，60 天、每个合约 1440 根小时线；池子为流动性前 50 个 U 本位永续，其中 2 个因覆盖不足被剔除（`IDOLUSDT` 235/1440、`DRVUSDT` 906/1440），实际参与检验 48 个。

## 六、统计口径上的两个坑（都已在测试里固定住）

1. **`ct` 规格会大幅高估拒绝率。** 对随机游走的价格序列用含趋势项的 ADF，5% 水平上的误拒率实测 31%（含常数项是 5%）。临界值表与数据生成过程要配对，不能顺手多放一个趋势项。
2. **p 值插值方向容易写反。** 统计量 -2.30 在 Engle-Granger 表下（5% 临界值 -3.34）应落在 p ≈ 0.35；方向写反会得到 p ≈ 0.004，从而把不合格的配对误判为协整。自检里对临界值锚点（5% → 0.05、10% → 0.10）做了固定。

## 七、局限

- **假协整风险**：在趋势型标的（meme 币、代币股）上，即使做了半段稳定性检验，仍可能出现"两条腿一起涨"的伪协整。名单里的 `BLESSUSDT:*` 系列尤其需要人工看一眼经济含义。
- **单窗口结论**：只用了最近 60 天，没有做滚动窗口的多期一致性检验（那属于 FR-07.2 的 Walk-Forward 范畴）。
- **未接入调度**：PRD 要求"每周日 UTC 02:00 自动执行"，本阶段只交付了可手动运行的命令，**没有**装定时任务；取数依赖 SSH 到 NAS，因此还不能在无人值守的服务器上跑。
- **p 值是近似值**：判定用临界值比较，p 值只用于排序与阅读。
- **未实现**：FR-07.2（Optuna/Walk-Forward 参数寻优）仍然没有做；本阶段不改变任何执行参数。

## 八、与在册配置的关系

本阶段不修改 `config.yaml`。`spread.pairs` 里当前的 `BTCUSDT:ETHUSDT`（`hedge_ratio=1.0`、`z_entry=2.0`、`z_exit=0.5`、`z_stop=3.5`）在本次检验里对应 β = 0.714、相关 0.978，但价差不平稳。若后续决定换标的，需要人工改配置并重启 worker，随后由影子盘 7 天验证（FR-07.3）给出 Sharpe 与回撤，再决定是否进入下一阶段评估。
