# 双腿价差套利影子盘与管理页（FR-07.3）

日期：2026-11-22。本阶段落地 PRD FR-07.3 的**影子验证**部分与管理页只读展示，接在[阶段三](spread-arbitrage-phase3-2026-11-22.md)之后。

## 边界

- 影子盘只消费 `get_ticker` / `get_orderbook` 公开只读行情；不加载交易凭据、不订阅私有流、不调用交易写接口。
- 环境固定为独立的 `shadow`，模拟记录落在 `shadow_trade`，与 paper 执行器的订单、持仓、现金与对账完全隔离。
- 不占执行租约，不改变 phase-two 的权限门槛；worker 调用影子盘失败只跳过当前币对，不影响主循环。
- 不修改运行参数、不生成配置文件、不灰度放量、不实盘晋级；页面只呈现模拟结果与人工审阅候选。

## 计算口径

- 复用阶段三滚动对数价差、Z-Score 信号和持久化样本窗口。成本门槛仅控制开仓，平仓和硬止损直接按各自的 Z 阈值判断。
- 两腿各自按成交方向检查可见深度，同时满足目标名义金额和 `min_depth_notional` 才能模拟开仓。逐档消耗深度，用实际吃到的最差一档加冲击成本作为保护价，按 tick/qty step 对齐。深度不足时只保留行情样本。
- 开仓记录每腿按 `fee_rate` 计算的手续费，以及相对中间价的滑点成本，已实现净盈亏为零。平仓或止损按开仓和退出时的中间价计算对数价差变化，沿用开仓对冲系数，一次扣除开仓手续费和滑点。模型按中间价结算退出，资金费为零。
- 每个配对同时最多有一笔模拟持仓。每笔平仓或止损都关联开仓 ID，结算后允许再次开仓。同一配对的同一采样时间桶最多写一条账本事件，累计盈亏沿入账顺序用最新余额结转。
- 不模拟排队、部分成交、保证金、强平、真实成交延迟或交易所撮合规则。

## 7 天验证与候选

`ShadowEngine.status()` 读取 `shadow_trade` 中最近 `observation_days`（默认 7 天）的当前版本账本事件。旧记录原样保留供审计，排除在持仓恢复、累计余额及审阅结果之外。已有公开行情样本仍可用于信号窗口预热。部署修复后从新账本重新积累观察数据。

- 模拟决策数（成功开仓及结算事件）、完整闭环数、逐日模拟盈亏、观察窗内累计模拟盈亏。盈亏按平仓或止损的 UTC 日期归属；
- 以完整闭环收益序列估算年化 Sharpe 与最大回撤；
- 2026-11-23 增补 `review_gate`、`pair_reviews` 与 `pair_candidates`：同一观察窗内按 `spread.pairs` 的每对合约分别计算决策数、闭环数、Sharpe、回撤与累计模拟盈亏。

**候选按单个配对判定**。PRD 的门槛针对"某组参数 + 某个标的"，所以 `promotion_candidate` 与 `pair_candidates` 都以按配对的结果为准：某个配对达标即使组合口径为负也会被标出；某个配对不达标也不会因为其他配对赚钱而被连带标出。汇总层的 `sharpe` / `max_drawdown` / `cumulative_pnl` 是所有配对盈亏交织后的参考口径——不同配对的盈亏没有共同的资金池语义，混成一条曲线会放大回撤，因此**不能**用它做门槛判定。

门槛仍为配置项 `min_sharpe`、`max_drawdown`，闭环样本不少于 5 笔。候选只是人工审阅提示；系统不会自动下发新参数，也不会进入灰度或实盘。FR-07.1/07.2 的协整重评估、Walk-Forward/Optuna 寻优在该阶段文档成文时尚未实现，后来已作为独立离线阶段落地；这里的候选字段仍不代表任何自动晋级。

## 管理页

控制台新增“影子盘”标签，分四块展示：

1. 启用状态、观察窗、模拟决策、完整闭环、模拟 Sharpe、最大回撤、累计模拟盈亏与晋升候选；
2. 最近 20 条模拟决策（动作、理由、净盈亏、深度状态与时间）；
3. 观察窗内逐日模拟盈亏；
4. 按配对审阅表：配对参数、决策/闭环数、Sharpe、回撤、净盈亏与候选标记（候选标记按单个配对判定），并明确数据来自 Web 启动时配置，`pending_restart` 时不得把新保存参数当作已生效。

页面沿用现有 CSP 与原生 JS/CSS，不引入内联脚本、外部资源或前端框架；只读展示，没有 Promote/Canary 按钮。
