# 双腿价差套利阶段二：持久化执行与线性腿对账

日期：2026-11-22。阶段一说明见 [阶段一交付](spread-arbitrage-phase1-2026-11-20.md)。

本阶段把配对逻辑接入独立的 paper 运行账户：信号入队、发送前提交物理订单、逐笔成交去重、对冲与退出、持仓和现金校准，以及检查点重启恢复。默认关闭；没有部署到 NAS，没有使用交易凭据，也没有开放真实发单入口。

## 执行与恢复

`spread/runner.py` 的 `SpreadExecutor` 是持久化执行入口；原有纯函数状态机仍可独立测试。

- 开仓冻结完整 `PairSignal`、账户 UID、执行约束及计时器。相同配对编号、相同载荷幂等返回；载荷冲突拒绝。
- 每条物理订单先落库；领取时先提交 `submitted_at + UNKNOWN/PENDING`，再调用适配器。回执、超时、任务取消和租约丢失均不能把已领取订单重新变成可发送订单。
- 确定拒单可记为 `REJECTED`；重复编号拒单仍按未知结果核实。受理回执不作为成交凭证。
- 被动腿有成交后按等名义价值对冲主动腿。配置中的 `hedge_ratio` 用于协整对数价差的统计；物理执行仍遵循 PRD 的等名义价值口径，不把 β 当作额外的下单数量倍数。主动腿的未成交余量只有在上一物理订单已确认终结后才能补单，防止把在途余量重复对冲。
- 被动腿超时先撤单，再按订单与逐笔成交判定 `ABORTED`，撤单受理不等于零成交。
- 滑点、追单窗口或裸敞口超限时，保留 `ERROR_UNHEDGED` 事实，继续取消归属开仓单并以 reduceOnly IOC 退出剩余持仓。异常状态产生后在同一次 tick 内继续安排保护动作。
- 平仓按本配对的实际剩余归属数量下单；逐笔平仓事实全部核对且无在途订单后才记录 `CLOSED`。未成交退出单终结后可按新盘口安排下一笔，不将受理回执当作已平仓。
- 终态后晚到成交不会倒退状态，但会重新打开该配对的持仓监控和退出处理。
- 发单和撤单共用每配对 10 秒 15 次的持久化预算；每次 tick 最多推进四轮，避免拒单死循环。

重启流程：恢复模拟交易所检查点 → 读取未完结配对 → 查询订单、成交、仓位与账户 → 校准。旧执行者停止及接管确认继续遵循原有租约规则，**不会自动越过 `NEEDS_CONFIRMATION`**；确认后清理本系统遗留开仓挂单、处理已成交敞口。外部订单只报差异，不接管或撤销。

## 账务与对账

新增迁移 `a612e47bc903`，接在阶段一 `3f7c1d92ab40` 后面：

- `spread_pair_trade.context` 保存冻结的信号、恢复标志、时间窗口与写入预算；`account_uid` 明确账户归属。
- `spread_execution` 保存逐笔成交，唯一约束为 `(environment, exec_id)`。相同编号不同价格、数量、费用或订单归属会阻断，不改写原事实。
- 缺少账户归属或冻结上下文的旧配对记录拒绝直接接管，需单独核实迁移。

`spread/reconciliation.py` 在每轮执行前校准：

1. 订单编号、合约、方向、数量、价格、订单类型、TIF、reduceOnly、交易所编号一致。
2. 订单累计成交量必须与逐笔成交之和一致；累计快照领先成交明细时保持不可信。
3. 以逐笔成交重建各配对剩余仓位，聚合后核对真实单向仓位；不以交易所仓位覆盖本地归属。
4. 现金以首次可信钱包余额为锚，重放已实现盈亏和实际手续费。保证金冻结只影响可用资金，浮盈只进入权益，不把合约名义本金按现货现金流计算。
5. 账户身份、USDT 现金、权益完整性、外部持仓/订单/成交均必须可解释。

`spread_reconciliation_log` 保存账户级与各活跃配对的双腿数量、名义价值、差异；正常且无变化的记录按 `reconciliation_interval_seconds`（默认 300 秒）落库，新增成交和差异变化即时落库。实际校准每轮运行，不因日志间隔延后。

## 模拟撮合与估值

`spread/paper.py` 的 `LinearPaperAdapter` 继承原模拟适配器，保持旧现货/期权接口。`DurablePaperAdapter` 使用此基类，模拟交易所写操作和行情撮合后保存检查点。

- 线性行情与现货行情使用独立命名空间，允许同名 `BTCUSDT` 存在于不同产品。
- 支持单向多空、PostOnly、IOC 部分成交撤余量、reduceOnly 动态截断及稳定订单编号。
- 保守 1x 抵押冻结持仓及挂单资金，避免挂单重复使用余额；费用默认按成交额的 `0.00055` 估算，独立版本化保存。
- 钱包只变动已实现盈亏及费用；风控权益为钱包现金加线性浮盈，使用独立的 `:linear-v1` 估值政策版本。
- 新鲜盘口可用中间价生成明确标注的合成 mark；缺失/过期报价不得按零风险估值。
- 检查点缺失但数据库已有套利订单时拒绝重置初始资金。

此模型不模拟真实 UTA 保证金、强平、资金费、撮合队列或真实成交延迟。合成 `account_mm_rate` 仅用于演练，不是交易所风险指标验收。

## worker 接入和配置

`TradingService` 在 `spread.enabled: true` 时切换至独立线性目录、线性腿对账与估值；原有基线、暂停、租约和接管要求继续生效。

启用条件同时由配置加载和启动代码检查：

- 只能使用 paper、USDT、unified 账户；远程执行器构造也直接拒绝。
- 需要独立数据库，不含旧现货/期权订单、库存或期权验证运行。
- 总开关和至少一个配对开关启用；旧策略不可同时启用，期权验证启动也被拒绝。
- 已有套利交易事实的数据库不能切回旧现货/期权模式运行。
- 套利配置变更需重启，已开配对仍使用冻结上下文。

受控的 worker 内部入口：

- `await service.open_spread(signal)`：要求账户身份、近期快照、对账、完整估值、风险基线、已确认租约与无活动暂停。
- `await service.close_spread(pair_trade_id, reason="...")`：按配对归属安排退出，在暂停新增风险期间仍可推进。

`PairSignal.notional` 是**每腿**预算；单组上限、权益比例与账户杠杆按**双腿总名义**预留和检查。例如每腿 100 USDT，占用单组 200 USDT 的名义预算。阶段二不允许活跃配对共享合约，避免单向净持仓下跨配对 reduceOnly 归属歧义。

这两个方法是现有 worker 内部 API，不是额外的无租约命令行发单进程。自动信号生成、独立 Web 控制接口及机器人命令尚未交付。默认配置不启用套利，也不会自动开仓。

## 尚未覆盖的实盘能力

- 真实订单、成交、仓位、资金流水的分页/查询窗口以及长期增量游标。
- 实际 UTA 混合账户保证金、资金费与交易所账单归因；目前未解释的现金变动会阻断。
- 常驻私有 WebSocket 到此持久化执行器的端到端消费；阶段一事件适配仍独立测试，阶段二 paper 由轮询和盘口更新推进。
- 自动协整筛选、滚动信号、Z 止损信号接入、Walk-Forward、影子盘及灰度晋升。
- 裸腿保护状态及持仓/现金差异会阻断新风险；尚未单独交付配对级告警订阅与机器人通知链路。
- 保证金率超过 75% 时目前对本账户全部归属仓位执行平仓，而非 PRD 所述等比例减仓；没有跨账户或外部仓位接管。
- 15ms 对冲、500ms 补偿、5 秒裸敞口或 `/panic` 的真实端到端时延指标。当前 worker 的秒级轮询不构成上述指标验收。
- 无人接管恢复、独立退出守护、长期容量和真实通知/灾备演练。

本阶段的完成标准是可持久化、可对账、可重启校准的独立 paper 配对闭环，不能据此启用真实资金。
